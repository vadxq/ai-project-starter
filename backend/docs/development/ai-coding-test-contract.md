# API 测试契约编写规则

## 目标

测试契约用于在实现接口前明确行为边界，让代码、测试和文档围绕同一组规则演进。

当新增或修改非平凡接口时，在 `docs/test/<domain>/README.md` 或独立契约文件中记录测试契约。

## 何时需要契约

以下情况需要写或更新契约：

- 新增公开 HTTP 接口
- 修改请求字段、响应字段或状态码
- 新增数据库写入行为
- 新增鉴权、权限、幂等、作用域隔离等规则
- 修改错误处理或边界条件

简单的健康检查、纯内部重构或不改变行为的整理可以只保留测试，不必新增契约。

## 测试命名

测试函数名必须描述行为：

- `<domain>_<action>_with_valid_payload_returns_success`
- `<domain>_<action>_with_missing_field_returns_bad_request`
- `<domain>_<action>_with_duplicate_resource_returns_conflict`
- `<domain>_<action>_without_auth_returns_unauthorized`

避免使用：

- `test_create`
- `test_api`
- `happy_path`

## 默认覆盖要求

按接口风险选择覆盖范围。

公开查询接口：

- 成功查询
- 空结果
- 参数非法
- 未知路由或错误方法

创建接口：

- 成功创建
- 必填字段缺失
- 字段格式非法
- 重复或唯一约束冲突
- 事务失败不留下半成品

更新接口：

- 成功更新
- 目标不存在
- 字段格式非法
- 并发或版本冲突

删除接口：

- 成功删除
- 重复删除
- 目标不存在
- 相关资源状态正确

鉴权或权限接口：

- 未鉴权返回 `401`
- 无权限返回 `403`
- 有权限成功
- 权限变化后行为同步变化

## 断言规则

HTTP 断言：

- 状态码
- 响应 JSON 的 `code`
- 响应 JSON 的 `message`
- 关键 `data` 字段
- 关键 `details` 字段

数据库断言：

- 新增记录数量
- 关键字段值
- 外键关系
- 审计字段
- 软删除字段
- 事务失败后的状态

安全断言：

- 响应不泄露密码、密钥、token secret 等敏感字段
- 错误响应不泄露内部 SQL、堆栈或连接串密码

## 示例：health

```markdown
# 接口契约：GET /health

## 元信息

- 业务域：health
- 访问范围：公开接口
- 行为类型：查询
- 测试文件：tests/router.rs

## 行为目标

- 进程可接收 HTTP 请求时返回存活状态。

## 前置条件

- 配置：无需特殊配置
- 数据库：不需要
- 登录态或凭证：不需要

## 请求约束

- method: GET
- path: /health

## 响应约束

- 成功状态码：200
- 成功响应：data.status = "ok"

## 数据状态变化

- 无

## 测试矩阵

| 场景 | 输入        | HTTP 状态 | 响应断言           | 数据断言 | 测试函数                     |
| ---- | ----------- | --------- | ------------------ | -------- | ---------------------------- |
| 成功 | GET /health | 200       | data.status = "ok" | 无       | health_route_returns_ok_json |
```
